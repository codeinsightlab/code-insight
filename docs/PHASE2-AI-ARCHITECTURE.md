# CodeInsight Phase 2 — AI Analysis Engine Architecture

## Overview

Phase 2 introduces the **AI analysis capability** of CodeInsight.

While Phase 1 focuses on extracting structural information from a Java/Spring Boot project,
Phase 2 focuses on **understanding and analyzing the project** using AI.

The goal is to provide meaningful engineering insights such as:

- Project summary
- Architecture explanation
- API capability overview
- Structural risk analysis
- Interactive project Q&A

This phase builds on the structured data generated by the scanner engine.

---

# Core Components

## 1. Structured Project Model

Purpose:

Provide a unified structure representing the scanned project.

Input:

- controllers
- endpoints
- entities
- fields
- javaFiles
- statistics

Output:

ProjectAnalysisContext

This model becomes the **input for AI analysis tasks**.

---

## 2. Analysis Context Builder

Purpose:

Prepare AI-friendly context for different analysis tasks.

Responsibilities:

- Reduce irrelevant data
- Build structured prompt context
- Prepare task-specific inputs

Context types:

### Project Overview Context

Used for:

- project summary
- technology stack description
- module explanation

### API Context

Used for:

- endpoint grouping
- API capability summary

### Entity Context

Used for:

- data model explanation
- core domain identification

### Risk Context

Used for:

- architecture risks
- structural inconsistencies

---

## 3. AI Analysis Orchestrator

Purpose:

Coordinate AI analysis tasks.

Responsibilities:

- select analyzer
- build prompt
- invoke LLM
- process results

Submodules:

### ProjectSummaryAnalyzer

Outputs:

- project description
- core functionality
- system overview

---

### ArchitectureAnalyzer

Outputs:

- architecture explanation
- module structure
- design pattern hints

---

### EndpointAnalyzer

Outputs:

- API categorization
- service capability description
- domain grouping

---

### RiskAnalyzer

Outputs:

- structural risks
- architecture suggestions
- naming inconsistencies
- potential design issues

---

### QAAnalyzer

Provides interactive Q&A over project structure.

Example questions:

- What does this project do?
- What APIs exist for order management?
- What entities represent core domain objects?

---

## 4. Prompt Template Engine

Purpose:

Manage reusable prompt templates.

Template categories:

- project-summary
- architecture-analysis
- endpoint-analysis
- risk-analysis
- qa-analysis

Each template should define:

- system instruction
- task description
- expected output format

---

## 5. LLM Gateway

Purpose:

Encapsulate all LLM provider integrations.

Responsibilities:

- model invocation
- timeout handling
- error handling
- logging

This abstraction allows switching LLM providers easily.

---

## 6. Analysis Result Formatter

Purpose:

Convert raw AI output into structured results.

Output format example:

- title
- summary
- bulletPoints
- risks
- suggestions
